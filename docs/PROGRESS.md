- **v0.6.0**: optional **Cluster tab** (OBD gauge cluster), logic ported from the owner's OBD-Gage-Cluster repo (Python/Kivy) to Kotlin/Compose.
  - **Hidden by default.** `Settings.showCluster` (default false, persisted, `DashRepository.setShowCluster`) with the "Cluster tab" switch in `ModeSettingsCard` (Health). Hidden = no tab, no Bluetooth permission request, no Bluetooth call of any kind: `ClusterPresenter` is inert until `setTabVisible(true)`. Tab bar when shown: Live, Trips, Health, Cluster (`DashTab.visible`). No driving restriction on this tab (the Driving lock only blocks Trips/Health and never forces a switch away from Cluster).
  - **Connection policy**: connects only while the Cluster tab is visible AND the app is active (`MainActivity` onResume/onPause feed `AndroidClusterPlatform.appActive`); leaving the tab or backgrounding closes the socket. BLUETOOTH_CONNECT is requested at runtime (API 31+) only when the tab is opened, once per open (the 5 s retries do not nag); granting it retries at once. Manifest: legacy BLUETOOTH/BLUETOOTH_ADMIN with `maxSdkVersion=30`, `BLUETOOTH_CONNECT`, `uses-feature bluetooth required=false`. No location permission for Bluetooth.
  - **Failure UI**: no "no dongle" mode. If it cannot connect the tab keeps its name and shows "Could not connect to the OBD dongle", a reason line (Bluetooth is off / no paired OBD adapter, pair it in the unit's Bluetooth settings / connection failed / permission needed / adapter did not answer / connection dropped), a Retry button and "Trying again every 5 seconds". The failure stays on screen during background retries.
  - **Dongle choice**: bonded devices, auto-pick by name hint (OBDLINK, OBDII, OBD, ELM, VLINK, V-LINK, VGATE, LINK; most specific first; `DeviceSelector`), optional "Dongle" row on the Cluster screen (Change opens a picker, persists `Settings.obdAddress`; a saved device that is no longer bonded falls back to auto).
  - **Protocol** (`obd/ObdProtocol`): init ATZ ATE0 ATL0 ATS0 ATSP6; PIDs 0104 load, 0111 throttle, 010F intake temp, GM mode 22 `221940` trans temp, 0105 coolant; reply parsing rejects NO DATA / ERROR / UNABLE TO CONNECT, strips SEARCHING/BUS INIT/STOPPED and non-hex, finds the prefix, takes byte A. SPP UUID 00001101-..., reflection `createRfcommSocket(1)` fallback for clones (`app/obd/BluetoothObdLink`).
  - **Session** (`obd/ObdSession`): 5 s auto-reconnect forever (Retry cuts the wait), staged trans failsafe exactly as ported: functional, then physical (ATSH7E1 before and ATSH7DF after each request) after 8 misses, then permanent fallback to coolant 0105 (relabelled "Coolant", 40-140 C, warn 118) after 8 more. Guards: a miss only counts when another PID answered in the same cycle, a stage that answered once is never escalated away from, the stage persists across reconnects and across leaving the tab (lives in the presenter for the app session, not across app restarts). Addition not in the original: a gauge whose PID misses 10 cycles in a row shows "--" instead of a stale number.
  - **Gauges** (all degC / %): Trans 20-150 C (amber 118, red 130), Coolant 40-140 (amber 118, red 125), Load 0-100 (amber 90), Throttle 0-100, Intake -20..80. Status line: "Live · <adapter>", "Trans temp: asking the transmission module", "Showing coolant temp instead".

## Known issues / risks
- **Cluster: unverified on a real dongle.** Never tested against a real ELM327, the truck's TCM, or the head unit's Bluetooth stack. First checks: pair the dongle in the unit's Bluetooth settings, turn on Health > Cluster tab, open it. Torque Lite (or similar) reading Engine Load is the quick proof that dongle and truck work. If trans temp never answers the dial relabels itself to Coolant after about 10 s (that is the designed fallback, not a bug). Clone adapters needing the channel-1 reflection fallback could not be tested. Whether the unit grants BLUETOOTH_CONNECT in a split-screen pane is unknown.
- **v0.5.0 unverified on hardware**: how the head unit's split-screen actually sizes the activity (and whether it honours resizeable activities, the IME inside a half pane, dialogs in a pane) is untested. Pane shape is judged only from the desktop sandbox.
- **Deferred from the review** (valid, not yet done): (a) auto-calibration of the IMU mounting - if the IMU is mounted flat/rotated vs the panel the G-ball reads 0 or wrong; `mountYawDeg` only fixes yaw; (b) `points` table grows ~1.3M rows/yr at 1 Hz - store every 2–3 s / on heading change, add (tripId,tMs) index, downsample route drawing; (c) distance across GPS gaps (tunnels) is under-counted (dt clamped to 5 s) - add haversine for 5–120 s gaps; (d) root composable recomposes at 10 Hz (split G into its own flow); (e) `max speed` could use a 3-sample median.
- Whether ACC-off suspends or hard-cuts power decides if the last ≤10 s of a trip survive; boot autostart can't start a location FGS on Android 14+ (use the ROM's autostart to launch the activity).
- Untested on hardware; sensor axis assumptions (screen faces rear, -Z = forward) may need `mountYawDeg`.
- GPS altitude is WGS84 ellipsoid (not MSL) on most devices → absolute altitude may be off by tens of metres; relative climb/grade fine.
- Head-unit ROMs may kill background services or block BOOT_COMPLETED → set app to autostart / "don't optimise battery" in the ROM.
- Odometer drifts vs. real odometer (GPS distance); re-set it occasionally.
- Trip start is delayed by `startHoldMs` (5 s); first ~40 m of a trip are not counted.
- Harsh-event thresholds (0.30 g accel / 0.35 g brake / 0.40 g corner) are guesses for a pickup.

## Decisions
- Hysteresis reading (v0.5.0): "+/- 24 dp" means the on/off band is T-24..T+24 around each threshold. First measurement uses the plain threshold.
- Tiny keeps the tab bar (40 dp) so navigation still works; compact Live omits the G-ball; `PaneSpec` lives in `core` (pure) while the CompositionLocal lives in `ui/Pane.kt`.
- Native Kotlin + Compose, not cross-platform: need foreground service, sensors, canvas gauges at 60 fps.
- Distance by integrating Doppler speed × dt (more accurate than position haversine at 1 Hz).
- One merged app for Live/Trips/Health (shared GPS/IMU service + DB). Markets Board is a **separate** app (internet-dependent, must not affect the speedometer).
- Metric only (owner in Canada). Fuel economy is L/100 km (lower = better), not km/L.
- minSdk 26 so `java.time` works without desugaring.
- No icons library (keeps APK small); text tabs.
- Shared code via a plain `srcDir` (not KMP plugin) to keep Android build simple; shared UI uses `collectAsState` (not lifecycle-aware) and `LocalBackHook` for platform back handling.
- UI is laid out at a fixed 440 dp design width (`DesignScale`) because head-unit densities are unknown.
