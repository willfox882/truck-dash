# Desktop sandbox (Windows / Linux / macOS)

Runs the **real** Truck Dash UI + trip engine on a desktop, fed by a simulated truck (synthetic GPS + IMU).
Nothing is mocked in between: `shared/` code is compiled into both the Android app and the sandbox.

## Run (Windows)
1. Install Java 17+ (e.g. Temurin 17 JRE from https://adoptium.net).
2. Put `truck-dash-sandbox.jar` and `run-sandbox.bat` in one folder, double-click the `.bat`
   (or `java -jar truck-dash-sandbox.jar`).

Build it yourself: `./gradlew :sandbox:sandboxJar` -> `sandbox/build/libs/truck-dash-sandbox.jar`
(dev run: `./gradlew :sandbox:run`).

## What you get
- Left: the 14.4" portrait head unit (9:16 frame, resizable window). Right: simulator controls.
- Scenarios: City loop, Highway climb, Hard-driving demo, Parked. Time 1x/5x/20x/60x, pause, "Skip 6 min"
  (lets the 5-minute trip-end timer fire). Manual sliders for speed (km/h) / turn rate / grade. Buttons for hard brake,
  floor it, sharp turns, GPS dropout. Passenger-mode toggle. Reset data.
- Starts with ~16 seeded trips (generated by running the real engine), fuel logs and maintenance items.
- Speed lock: drive above 5 km/h and Trips/Health go "PARKED ONLY" (switch on Passenger mode to bypass).
- Esc backs out of a trip detail.

## What it can NOT tell you
Real sensor axes/mounting, real GPS quality, ROM background-service behaviour, touch feel on the actual panel.

## Headless screenshots (for agents / CI)
`./gradlew :sandbox:screenshots` renders Live / Trips / Trip detail / Health PNGs to `sandbox/build/screenshots/`
without a window (Skia software raster). Look at them after any UI change.

## Layout
`sandbox/src/main/kotlin/com/truckdash/sandbox/`: `VehicleSim.kt` (physics + scenarios), `SimController.kt`
(feeds DriveEngine), `MemoryStore.kt` (in-memory Room stand-in + repo), `Session.kt` (wiring + history seeding),
`SandboxApp.kt` (window UI), `Screenshots.kt`, `Main.kt`. Tests: `sandbox/src/test/.../SimTests.kt`.
